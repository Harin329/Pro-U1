This is a golf ball tracking dashboard built with [Next.js](https://nextjs.org) and Supabase.

## Dashboard features (MVP)

- 🏆 Best ball card based on lowest average score from `ball_stats`
- 📊 Ball comparison table (`score`, `FW%`, `GIR%`, `putts`, `up-and-down %`)
- 📝 Recent rounds list (latest 5 rounds)
- ✍️ In-app logger to add a ball, create a round, and save holes 1-18

## Random course picker

Can't decide where to play? Open [`/course-picker`](http://localhost:3000/course-picker) (also linked from the
dashboard header):

- **Starting point:** one-tap Vancouver, BC and Seattle, WA presets, "Use my location", or search any city,
  address or postal code (geocoded with OpenStreetMap Nominatim).
- **Radius:** 5–320 km or 5–200 mi.
- **Filters:** access type (public / semi-private / private, with **private excluded by default**), 18 or 9
  holes, and an option to skip par-3s and pitch-and-putts (on by default).
- **Pick:** draws a random club from the matching pool, without repeats until you've cycled through them all.
  Multi-course facilities count once. You get directions, a Google Maps link and the TheGrint scorecard, and you
  can hide courses you never want suggested.

Preferences (location, radius, filters, hidden courses) are saved in your browser.

### Where the course data comes from

Courses come from [TheGrint's course directory](https://thegrint.com/golf-courses). Each region page (every US
state, Canada, the UK & Ireland countries and ~170 other countries) embeds every course's coordinates and access
type. `GET /api/golf/courses?lat=…&lng=…&radiusKm=…` loads only the regions near the search point (cached for a
day) and returns the courses within the radius.

- `src/data/golf/regions.json` maps 1° grid cells to Grint regions, so a search knows which pages to load.
- `src/data/golf/snapshot.json` is an offline copy of Washington and British Columbia courses. It is used
  automatically if TheGrint can't be reached, so Seattle and Vancouver searches always work.

Both files are generated by crawling TheGrint (~230 pages, a few minutes). Re-run occasionally to pick up new
courses or regions:

```bash
npm run golf:refresh-courses
```

Use `npm run golf:refresh-courses -- --snapshot-only` to refresh just the WA/BC snapshot. The script needs
Node 22.18+ (it runs TypeScript directly).

## Getting started

1. Install dependencies.
2. Copy `.env.example` to `.env.local`.
3. Add your Supabase project URL and anon key.
4. Run the app.

The app reads these environment variables:

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`

Then run the development server:

```bash
npm run dev
# or
yarn dev
# or
pnpm dev
# or
bun dev
```

Open [http://localhost:3000](http://localhost:3000) with your browser to view the dashboard.

You can customize the dashboard in `src/app/page.tsx`.

## Expected Supabase schema

This UI expects:

- A `rounds` table with at least: `id`, `course_name`, `total_score`, `date`
- A `ball_stats` view with at least:
	- `ball_id`, `brand`, `model`, `rounds_played`
	- `avg_score`, `avg_putts`, `fairway_pct`, `gir_pct`, `up_and_down_pct`

## Notes

If Supabase environment variables are missing, the dashboard will show a setup notice instead of crashing.

If you see `Unable to load all dashboard data` with a `division by zero` message, recreate the
`ball_stats` view using `supabase/ball_stats_view.sql` in your Supabase SQL editor.
